# Telemetry Ingest

Status: **draft**

Shapes & RPCs: [`telemetry.proto`](../../franz/api/franz/v1/telemetry.proto)
(`TelemetryService.PublishIndicatorSamples`, `ReportConsumerGroups`);
[`governance.proto`](../../franz/api/franz/v1/governance.proto) (`Indicator`,
plus the `CreateIndicator` / `UpdateIndicator` / `DeleteIndicator` /
`ListIndicatorSamples` RPCs added for this doc).

How Telemetry Agents (`003.9`) feed Franz the signals governance (`003.8`) reads.

## Concepts

Two inbound streams, both gRPC-only, both agent-authenticated (auth model
deferred — stub in the near term):

- **Indicator samples** — a numeric/boolean value for one indicator on one
  resource at one time.
- **Consumer-group observations** — which consumer groups an agent saw on which
  Kafka topics.

Franz **stores both as append-only time series**, prunes by age, and serves
history and "current" views.

## Indicators are pre-registered

An `Indicator` must exist before Franz accepts samples for it. Registration is an
admin action (`CreateIndicator`): `name`, `unit`, `applies_to` (entity),
`staleness_threshold`, optional `source_agents`.

- `PublishIndicatorSamples` for an unknown `indicator` → **rejected**
  (`FAILED_PRECONDITION`). No auto-creation.
- `CreatePolicy` referencing an unknown `indicator` → **rejected** (resolves
  `003.8` OQ6).
- A sample whose `resource_entity` ≠ the indicator's `applies_to` → rejected.
- `value` is a string encoded per `unit`; Franz validates it parses
  (number / duration / boolean) but does not bound it.

## Sample storage

`indicator_sample` is **append-only**: `(indicator, resource_frn,
resource_entity, value, sample_at, received_at)`.

- **Retention**: samples older than a global default (**30 days**) are pruned by a
  nightly job.
- **"Current" value** for governance = the row with the greatest `sample_at` per
  `(indicator, resource_frn)` (kept fast with an index, or a maintained
  `indicator_latest` projection).
- **Out-of-order**: a sample with `sample_at` older than the current latest is
  stored (it's history) but does **not** become "current" and does **not**
  trigger evaluation.
- **History API**: `ListIndicatorSamples(indicator, resource_frn, from, to)`.
- `Indicator.health` is `STALE` when the latest `sample_at` is older than
  `staleness_threshold`; `last_sample_at` is maintained on write.

## Consumer-group observations

`observed_consumer_group` is **append-only**: `(group_name, kafka_topic_id,
async_channel_id, client_frn, custom, reported_by_agent, observed_at)`.

- Reported by `ReportConsumerGroups`; the agent resolves `kafka_topic` and, where
  it can, the `client_frn` (default group name `<client>.<topic>` → prefix match;
  custom names → best-effort, may be empty — `003.10`).
- **Retention**: 30 days, nightly prune.
- **"Current" view** (`ListObservedConsumerGroups`, `003.10`) = distinct
  `(group, topic)` with the latest `observed_at`; the raw sightings are the
  history behind it.

## Governance coupling

`003.8` OQ4 is **event-driven**: a successful `PublishIndicatorSamples` that
updates the "current" value for `(indicator, resource_frn)` synchronously (or via
an in-process queue) triggers evaluation of every enabled Policy bound to that
indicator for that resource. There is no cooldown (`003.8` OQ3), so ingest rate
directly bounds action rate.

Consumer-group observations do **not** trigger governance; they are read-only
context.

## Open questions

1. **Agent authentication** — how an agent proves identity on the gRPC stream
   (mTLS / token). Deferred to the agent-auth ADR; stub = accept any caller.
2. **Sample batching / rate** — max samples per call, per-agent rate limits, and
   backpressure when the governance queue is deep.
3. **Retention override** — global 30 days vs. per-indicator retention; and
   whether history should live in Postgres at all vs. only "current" + an
   external TSDB.
4. **Ingest → eval delivery** — synchronous in the RPC handler (simple,
   couples latency) vs. an internal durable queue (survives restart, adds a
   component).
5. **`source_agents` maintenance** — auto-append an agent on first sample, or
   keep it purely declarative on the `Indicator`.
6. **Derived / aggregate indicators** — whether Franz ever computes an indicator
   from others, or that is always the agent's job (see `003.8` Telemetry Q2
   discussion — windowing lives in the agent).
