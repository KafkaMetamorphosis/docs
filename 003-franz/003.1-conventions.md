# Franz API Conventions

Status: **ready**

Shapes: [`common.proto`](../../franz/api/franz/v1/common.proto)

Cross-cutting rules every Franz entity and RPC follows. Every other `003.x`
document assumes these.

## Realm

A **realm** is the tenant and authorization boundary. Every resource belongs to
exactly one realm; names are unique only within `(realm, resource-type)`; access
tokens and scopes are realm-scoped. How realms are provisioned is out of scope
here.

## FRN

Every resource has an **FRN** (Franz Resource Name) — an opaque, globally-unique
identifier assigned by Franz:

```
frn:<realm>:<resource-type>:<name>
```

- `resource-type` — kebab-case: `async-channel`, `kafka-cluster`, `kafka-topic`,
  `agent`, `client`, `policy`.
- `name` — the resource's own `name` field (below).

The FRN is **server-assigned and immutable**. Clients never send it in a request;
they reference resources by `name` within the relevant service.

### Prefix

`frn` is the default prefix. A deployment may override it with the control-plane
config key `resource_prefix` (env `FRANZ_RESOURCE_PREFIX`) — e.g.
`resource_prefix: acme` renders `acme:<realm>:<resource-type>:<name>`. The value
must match `^[a-z][a-z0-9]*$`, 2–16 characters.

- The prefix is **fixed at bootstrap** — read once at startup and constant for the
  life of the deployment. Changing it afterwards is an operator action, out of
  scope here.
- Franz **stores FRNs without the prefix** (the bare
  `<realm>:<resource-type>:<name>` path) and prepends the configured prefix only
  when rendering a response. Parsing accepts the configured prefix and always
  accepts the literal `frn:` and `orn:` prefixes as aliases, so an identifier
  copied from another deployment still resolves.

## Resource identity and naming

- **`name`** is the primary key within a service. Client-provided at create,
  **immutable** thereafter, referenced in every `Get` / `Update` / `Delete` and in
  gateway paths (`/v1/kafka/clusters/{name}`).
- `name` matches `^[a-z0-9]([a-z0-9._-]*[a-z0-9])?$`, 1–200 chars — `.`, `-` and
  `_` are all allowed (`franz.billing-events.v1-p0`, `br-prod-s8-kafka-01`).
- Franz-generated names (Kafka Topics) follow a documented algorithm — see
  `003.4-async-channel.md`.

## Label selectors

Wherever a "selector" appears — `List*Request.selector`, `Principal.labels`, and
the *value* of the reserved `franz.affinity/selector` label — it uses **one
grammar**: a comma-separated list of requirements, all AND-ed.

| Requirement | Matches when |
|---|---|
| `key=value` | the label exists and equals `value` |
| `key!=value` | the label is absent or does not equal `value` |
| `key IN (a, b, c)` | the label exists and is one of the listed values |
| `key NOT IN (a, b)` | the label is absent or not in the list |
| `key` | the label key exists (any value) |
| `!key` | the label key does not exist |

Whitespace around `,`, `=`, `!=`, `IN`, `(` and `)` is insignificant. Values are
bare tokens; wrap in `"…"` if a value contains a space, comma, or bracket. An
**empty selector matches everything**.

This supersedes the older `selector:key=value` form and any per-notation
variations — it is the one selector grammar.

## Reserved labels

Franz reserves the **`franz.*`** label prefix. Reserved labels follow Kubernetes
label conventions — `<prefix>/<name>`, where `<prefix>` is a DNS subdomain and
`<name>` is `[A-Za-z0-9]([A-Za-z0-9._-]*[A-Za-z0-9])?` (≤63 chars). The set of
reserved prefixes is **open** — new ones may be added without a breaking change.

Defined so far (channel↔cluster placement semantics in
`003.7-placement-and-selection.md`; agent↔cluster scoping in
`../005-gregor-samsa/README.md` §1.2 and `DECISIONS.md` ADR-API-011):

| Prefix / label | On | Purpose |
|---|---|---|
| `franz.affinity/*` | Async Channel | place the channel's shards on clusters that **match** (`franz.affinity/selector`, `franz.affinity/shard-size`, `franz.affinity/weight` — `003.7`) |
| `franz.antiaffinity/*` | Async Channel | place on clusters that do **not** match (`franz.antiaffinity/selector`; negation lives here, not in the selector grammar) |
| `franz.taint` | Kafka Cluster | `<name>:<effect>`, `effect ∈ { no-creation, drain }` — repel channels that don't tolerate it (`003.7`) |
| `franz.taint/toleration` | Async Channel | `<name>:<effect>` (comma-separated for several) — tolerate a matching cluster taint |
| `franz.default-kafka-config/*` | Agent | advisory Kafka-config defaults the console pre-fills into a Kafka Cluster form when this agent is the linked provider (`003.9`, ADR-API-010). Key = a `cluster_configuration` key (`partitions`, `replication-factor`, `retention.ms`, `kafka-version`, …). The meta-key `available-versions` carries a comma-separated list for the version picker. **Never enforced** — see `../004-local-kafka-docker-agent/`. |
| `franz.placement-selector/*` | Agent | a Resource Provider agent's **scope**: the Kafka Clusters it reconciles. Each `franz.placement-selector/<key>=<value>` must be matched by the cluster's `franz.placement/<key>=<value>`. A **plain conjunction of exact key/value pairs — NOT the selector grammar below.** An agent with **no** `franz.placement-selector/*` labels matches **nothing** (a deliberate departure from "empty selector matches everything", so a misconfigured agent cannot claim the whole fleet). ADR-API-011. |
| `franz.placement/*` | Kafka Cluster | the cluster's placement coordinates that `franz.placement-selector/*` matches against, e.g. `franz.placement/env=prod`, `franz.placement/region=us-east-1`. Extra keys the agent does not select on are ignored. |

Non-`franz.*` labels are free-form metadata and are what the non-placement
selectors (`List.selector`, `Principal.labels`, and the channel↔cluster
`franz.affinity/selector` / `franz.antiaffinity/selector`) match against.

> A Kafka Cluster's own Kafka config lives in its typed `cluster_configuration`
> map (`003.3`), **not** in labels. `franz.provisioning/*` (a former Kafka-Cluster
> label prefix) is retired by ADR-API-010.

## Wildcards

`*` is a **glob** (not a regex): it matches any run of zero or more characters. It
is allowed in:

- FRN principals in an access policy (`frn:acme-platform:client:billing-*`),
- label **values** in a selector (`org.com/team=billing-*`).

It is **not** allowed in label keys. A literal asterisk is `\*`. A lone `*` means
"match all".

## Pagination

List RPCs embed `PageRequest` / return `PageResponse` (`common.proto`).

- `page_size` — items per page. `0` means the server default (50). Capped at 1000.
- `page_token` — **opaque**; pass back the previous response's `next_page_token`.
  Do not parse it. It is only valid for a request with the *same* filters; change
  `selector` or a typed filter and you must start from page 1.
- `next_page_token` empty ⇒ last page.
- `total_size` — best-effort; may be `0` when a count would be expensive.
- **Ordering** — by `name` ascending unless the RPC documents otherwise; stable
  across pages.

## List filtering

- `selector` (string) — a label selector (grammar above) applied to the resource's
  `labels`.
- Typed filters — some List RPCs also expose scalar filters
  (`ListKafkaTopicsRequest.async_channel` / `.kafka_cluster`,
  `ListAgentsRequest.type`). Typed filters and `selector` are **AND**-combined.

## Update semantics

`Update*Request` carries the client-settable fields explicitly **plus a
`google.protobuf.FieldMask update_mask`**.

- Only fields named in `update_mask` are applied; everything else is left
  unchanged. An **empty mask is rejected** (`INVALID_ARGUMENT`).
- A masked `map` or `repeated` field is **replaced wholesale** — send the full
  desired value; there is no per-key / per-element patch.
- `name` is immutable and cannot appear in the mask.
- Create and Update requests never embed the resource message and never contain
  server-assigned fields (`frn`, `created_at`, `updated_at`, derived state).

## Timestamps

All timestamp fields use the **`_at`** suffix and type `google.protobuf.Timestamp`.

- **`created_at` / `updated_at`** — server-managed, on every resource. The audit pair.
- Domain-event timestamps — `last_contact_at`, `last_fired_at`, `last_sample_at`,
  `last_seen_at`, `sample_at`, `observed_at`, `occurred_at`; semantics per field.

## Errors

gRPC status codes:

| Code | Used for |
|---|---|
| `INVALID_ARGUMENT` | malformed request — bad selector, unknown field, `EFFECT_UNSPECIFIED`, empty `update_mask` |
| `NOT_FOUND` | no resource with that `name` |
| `ALREADY_EXISTS` | create with a name already taken |
| `FAILED_PRECONDITION` | operation invalid for current state (delete a cluster with live topics; act on a soft-deleted resource) |
| `PERMISSION_DENIED` | scope check failed (see `003.2-api-authorization.md`) |
| `RESOURCE_EXHAUSTED` | quota — access-policy statement cap, page size |

Field-level validation failures attach `google.rpc.BadRequest` with one
`FieldViolation` per bad field. Governance dry-run rejections and policy-shape
errors use the same mechanism.

## Custom methods

Non-CRUD operations use the AIP custom-method form: gRPC method `VerbResource`
(`PauseAsyncChannel`, `SetConsumption`, `DryRunPolicy`), gateway route
`POST /…/{name}:verb`.
