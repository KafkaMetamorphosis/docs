# Agents

Status: **ready**

Shapes & RPCs: [`agent.proto`](../../franz/api/franz/v1/agent.proto) — `Agent`,
`AgentType`, `AgentStatus`, `AgentService` (CRUD + `Pause`/`Resume` +
`RotateAgentToken`). Interaction contracts:
[`agent_cluster_provider.proto`](../../franz/api/franz/v1/agent_cluster_provider.proto)
(Cluster Provider) and
[`agent_resource_provider.proto`](../../franz/api/franz/v1/agent_resource_provider.proto)
(Resource Provider).

> This document covers the **Agent registry** — the control-plane record and its
> lifecycle. How an agent exchanges work, results, or telemetry with Franz is a
> **separate ADR** per agent type — for Cluster Providers,
> `../004-local-kafka-docker-agent/`; for Resource Providers,
> `../005-gregor-samsa/` (ADR-API-011). Telemetry ingest is shared
> (`TelemetryService`, `003.14`).

## Concepts

An **Agent** is Franz's record of an external program that connects **to** Franz
over gRPC to do fleet work — **Franz never calls an agent**. Registering an agent
creates the identity and its metadata; it does not start anything.

`type` is an **organisational filter only**. It does not change how the agent
connects, what it is allowed to do, or how Franz treats it — those come from the
agent's credentials and the (future) interaction model.

| Type | Does | Example |
|---|---|---|
| `CLUSTER_PROVIDER` | stands up and maintains a substrate (Kafka cluster, RabbitMQ, …) | — |
| `RESOURCE_PROVIDER` | realises individual resources (Kafka topics, queues) | Gregor Samsa |
| `TELEMETRY_AGENT` | publishes indicator + consumer-group telemetry | Odradek |
| `CUSTOM` | anything else | — |

## Key fields

| Field | Notes |
|---|---|
| `name` | Client-provided, immutable, realm-unique. |
| `frn` | Server-assigned. |
| `type` | `AgentType`; organisational filter (also a `ListAgents` filter). |
| `labels` | Free-form metadata **and** an extension point — owner, team, environment. Reserved prefixes: `franz.default-kafka-config/*` (advisory config defaults the console pre-fills into a Kafka Cluster form, see below) and `franz.placement-selector/*` (agent-watch scoping, Gregor Samsa / `003.1`). |
| `status` | `AgentStatus` — lifecycle: `ACTIVE` / `PAUSED` / `DELETED`; server-managed. See below. |
| `created_at` / `updated_at` | Audit pair. |

`CreateAgent` returns a **one-time bearer token** (`CreateAgentResponse.token`);
Franz stores only its hash. The agent presents it in gRPC `authorization`
metadata; `RotateAgentToken` issues a new one and invalidates the old. This
credential is self-contained — it does **not** depend on `003.2` (still a
placeholder). Interaction contracts (e.g. `../004-local-kafka-docker-agent/`) run
over this token. An agent's live gRPC connection is observable but does not change
`AgentStatus` — a derived "connected" flag is a possible later refinement.

Liveness / health (last contact, connected vs. stale) is **not modelled** — see
Deferred.

### Advertised defaults

An agent may carry **`franz.default-kafka-config/*`** labels on its own `labels`
map (ADR-API-010) — e.g. `franz.default-kafka-config/partitions=4`,
`franz.default-kafka-config/kafka-version=3.9.0`,
`franz.default-kafka-config/available-versions=3.7.0,3.9.0,4.0.0`. Each key is a
`KafkaCluster.cluster_configuration` key; `available-versions` is a meta-key
carrying a comma-separated list for the console's version picker.

Purpose is **console UX only**: when an operator points a Kafka Cluster at this
agent (`KafkaCluster.cluster_provider_agent`), the console pre-fills the cluster's
`cluster_configuration` form section from these labels. Franz **never enforces**
them — it does not validate a cluster's config against the linked agent, and
`cluster_provider_agent` stays an unvalidated string (see Cross-entity behavior).

An operator sets these labels in the console, or they are installed when the
agent is registered — the local-kafka-docker-agent's defaults ship in its
local-dev DB seed (`franz/local/seed/`, `../004-local-kafka-docker-agent/`).

> The former structured `provisioning_labels` / `ProvisioningLabelSpec` schema
> (ADR-API-008) is removed by ADR-API-010.

## State transitions

`AgentStatus` is a lifecycle machine, mirroring Kafka Cluster (`003.3`):

```
(register) ──▶ ACTIVE ──PauseAgent──▶ PAUSED
                 ▲──────ResumeAgent──────┘
   ACTIVE / PAUSED ──DeleteAgent──▶ DELETED   (terminal)
```

- `ACTIVE` — registered and eligible to receive work.
- `PAUSED` (`PauseAgent`) — registered but Franz hands it no work. `ResumeAgent`
  returns it to `ACTIVE`. What "no work" means precisely depends on the
  interaction ADR.
- `DELETED` — soft delete; the record is retained for audit and the `name` is not
  freed.

## Invariants

- `name` is unique per realm and immutable.
- `status` is server-managed; clients change it only through
  `PauseAgent` / `ResumeAgent` / `DeleteAgent`, never through `UpdateAgent`.
- `CreateAgent` / `UpdateAgent` carry only client-owned fields — `name`, `type`,
  `labels` — never server-assigned ones (`CreateAgentResponse` additionally
  returns the token).
- `franz.default-kafka-config/*` labels are **advisory** — Franz stores and
  serves them but never validates a Kafka Cluster's config against them.
- Registration is inert: it never establishes a connection or schedules work.
- The bearer token is shown once and stored hashed; `RotateAgentToken` is the
  only way to obtain a replacement.
- Any operation on a `DELETED` agent fails with `FAILED_PRECONDITION`.

## Cross-entity behavior

- **Kafka Cluster** (`003.3`) — a `CLUSTER_PROVIDER` may be named by many clusters
  via `KafkaCluster.cluster_provider_agent`. That link is an **unvalidated
  string**: deleting or renaming the agent does not update the clusters, and a
  cluster may name an agent that does not exist. The provider watches the clusters
  it owns and reports what it provisioned (`KafkaCluster.provider_status`, an
  append-only event log) — contract in `../004-local-kafka-docker-agent/`.
- **Kafka Topic** (`003.6`) — a `RESOURCE_PROVIDER` reconciles the real topics
  for the async-channel shards Franz streams it. Its scope is label-based
  (`franz.placement-selector/*` on the agent ↔ `franz.placement/*` on the
  cluster — `003.1`), **not** an FK: no field on `KafkaCluster` names it, and an
  agent with no selector labels is inert. Contract in `../005-gregor-samsa/`
  (ADR-API-011).
- **Governance** (`003.8`) — a `TELEMETRY_AGENT` publishes the `Indicator` samples
  and consumer-group observations policies read; `Indicator.source_agents` lists
  the agents feeding each indicator. Ingest shapes are in `telemetry.proto`.
- **Clients** (`003.10`) — observed consumer groups are reported by a
  `TELEMETRY_AGENT` (`ObservedConsumerGroup.reported_by_agent`).

## Deferred to a later ADR

- The agent ↔ Franz **interaction model** — how agents receive work, report
  results, recover from errors, and are scoped. Cluster Providers:
  `../004-local-kafka-docker-agent/`. Resource Providers + shared telemetry
  ingest: `../005-gregor-samsa/` (ADR-API-011). A standalone Telemetry Agent
  contract beyond `TelemetryService` is still owed.
- **Agent liveness / health** — last-contact tracking and a connected-vs-stale
  signal. Deliberately not modelled now; to be added if it proves necessary.
- The **telemetry ingest** semantics behind `telemetry.proto`.
- **Agent authentication** — how an agent proves its identity when it connects.

## Open questions

1. **Endpoint namespace** — `AgentService` is under `/v1/kafka/agents`, but a
   Cluster Provider may manage non-Kafka substrate; `/v1/agents` is arguably
   right.
2. **`type` mutability** — should `UpdateAgent` allow changing an agent's `type`
   after registration, or is it immutable like `name`?
3. **Delete while referenced** — when a cluster still names the agent in
   `cluster_provider_agent`: allow (dangling string, per `003.3`), block, or
   soft-delete?
4. **`PAUSED` semantics** — exactly what Franz withholds from a paused agent
   (new work only, or also in-flight); resolvable once the interaction ADR lands.
5. **`labels` as work-scoping** — whether responsibility (which clusters /
   resources an agent handles) is expressed through `labels` or a dedicated
   field added later.
