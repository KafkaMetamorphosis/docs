# Agents

Status: **ready**

Shapes & RPCs: [`agent.proto`](../../franz/api/franz/v1/agent.proto) — `Agent`,
`AgentType`, `AgentStatus`, `AgentService`.

> This document covers the **Agent registry** — the control-plane record and its
> lifecycle. How an agent exchanges work, results, or telemetry with Franz is a
> **separate ADR** (see Deferred).

## Concepts

An **Agent** is Franz's record of an external program that connects **to** Franz
over gRPC to do fleet work — **Franz never calls an agent**. Registering an agent
creates the identity and its metadata; it does not start anything.

`type` is an **organisational filter only**. It does not change how the agent
connects, what it is allowed to do, or how Franz treats it — those come from the
agent's credentials and the (future) interaction model.

| Type | Does | Example |
|---|---|---|
| `CLUSTER_PROVIDER` | stands up and maintains a substrate (Kafka cluster, RabbitMQ, …) | — |
| `RESOURCE_PROVIDER` | realises individual resources (Kafka topics, queues) | Gregor Samsa |
| `TELEMETRY_AGENT` | publishes indicator + consumer-group telemetry | Odradek |
| `CUSTOM` | anything else | — |

## Key fields

| Field | Notes |
|---|---|
| `name` | Client-provided, immutable, realm-unique. |
| `orn` | Server-assigned. |
| `type` | `AgentType`; organisational filter (also a `ListAgents` filter). |
| `labels` | Free-form metadata **and** an extension point — owner, team, environment, and a candidate basis for future work-scoping rules. |
| `status` | `AgentStatus` — lifecycle: `ACTIVE` / `PAUSED` / `DELETED`; server-managed. See below. |
| `created_at` / `updated_at` | Audit pair. |

Liveness / health (last contact, connected vs. stale) is **not modelled** — see
Deferred.

## State transitions

`AgentStatus` is a lifecycle machine, mirroring Kafka Cluster (`003.3`):

```
(register) ──▶ ACTIVE ──PauseAgent──▶ PAUSED
                 ▲──────ResumeAgent──────┘
   ACTIVE / PAUSED ──DeleteAgent──▶ DELETED   (terminal)
```

- `ACTIVE` — registered and eligible to receive work.
- `PAUSED` (`PauseAgent`) — registered but Franz hands it no work. `ResumeAgent`
  returns it to `ACTIVE`. What "no work" means precisely depends on the
  interaction ADR.
- `DELETED` — soft delete; the record is retained for audit and the `name` is not
  freed.

## Invariants

- `name` is unique per realm and immutable.
- `status` is server-managed; clients change it only through
  `PauseAgent` / `ResumeAgent` / `DeleteAgent`, never through `UpdateAgent`.
- `CreateAgent` / `UpdateAgent` carry only `name`, `type`, `labels` — no
  server-assigned fields.
- Registration is inert: it never establishes a connection or schedules work.
- Any operation on a `DELETED` agent fails with `FAILED_PRECONDITION`.

## Cross-entity behavior

- **Kafka Cluster** (`003.3`) — a `CLUSTER_PROVIDER` may be named by many clusters
  via `KafkaCluster.cluster_provider_agent`. That link is an **unvalidated
  string**: deleting or renaming the agent does not update the clusters, and a
  cluster may name an agent that does not exist.
- **Kafka Topic** (`003.6`) — a `RESOURCE_PROVIDER` reconciles the real topics;
  the mechanism is the interaction ADR.
- **Governance** (`003.8`) — a `TELEMETRY_AGENT` publishes the `Indicator` samples
  and consumer-group observations policies read; `Indicator.source_agents` lists
  the agents feeding each indicator. Ingest shapes are in `telemetry.proto`.
- **Clients** (`003.10`) — observed consumer groups are reported by a
  `TELEMETRY_AGENT` (`ObservedConsumerGroup.reported_by_agent`).

## Deferred to a later ADR

- The agent ↔ Franz **interaction model** — how agents receive work, report
  results, recover from errors, and are scoped.
- **Agent liveness / health** — last-contact tracking and a connected-vs-stale
  signal. Deliberately not modelled now; to be added if it proves necessary.
- The **telemetry ingest** semantics behind `telemetry.proto`.
- **Agent authentication** — how an agent proves its identity when it connects.

## Open questions

1. **Endpoint namespace** — `AgentService` is under `/v1/kafka/agents`, but a
   Cluster Provider may manage non-Kafka substrate; `/v1/agents` is arguably
   right.
2. **`type` mutability** — should `UpdateAgent` allow changing an agent's `type`
   after registration, or is it immutable like `name`?
3. **Delete while referenced** — when a cluster still names the agent in
   `cluster_provider_agent`: allow (dangling string, per `003.3`), block, or
   soft-delete?
4. **`PAUSED` semantics** — exactly what Franz withholds from a paused agent
   (new work only, or also in-flight); resolvable once the interaction ADR lands.
5. **`labels` as work-scoping** — whether responsibility (which clusters /
   resources an agent handles) is expressed through `labels` or a dedicated
   field added later.
