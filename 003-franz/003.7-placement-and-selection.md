# Placement and Selection

Status: **draft**

Shapes: [`async_channel.proto`](../../franz/api/franz/v1/async_channel.proto) (channel
`labels`), [`kafka.proto`](../../franz/api/franz/v1/kafka.proto) (cluster `labels`,
`KafkaTopic.kafka_cluster`). No dedicated RPC — placement is a side effect of
Async Channel create / update and cluster / label changes.

## Concepts

**Placement** decides which Kafka Cluster each of an Async Channel's shards
(`003.4`, `003.6`) lives on. It runs when a channel is created, when its
`franz.*` labels change, when its shard count changes, when a cluster's labels or
`state` change, and periodically (a **retry sweep**) for any shard that is not
yet placed.

Placement is driven **entirely by labels** — there is no cluster field on the
channel. The channel declares what it wants via reserved `franz.*` labels; each
cluster describes itself with `franz.*` labels; Franz matches them.

Channel create **always succeeds**. Per **ADR-API-009** a `kafka_topic` row is
materialised **only once placement has picked a cluster for that shard** — an
unplaced shard is a *missing* row, not a row with `kafka_cluster = NULL`.
`GetAsyncChannel` reports progress as "M of N shards placed" by counting rows;
the retry sweep creates the remaining rows as clusters become eligible.

## Placement inputs

### On the Async Channel (`AsyncChannel.labels`)

| Label | Meaning |
|---|---|
| `franz.affinity/selector` | A `003.1` selector expression. A cluster is a **candidate** only if its labels satisfy it. |
| `franz.antiaffinity/selector` | A `003.1` selector expression. A candidate is **excluded** if its labels satisfy it. Negation lives here, not in the selector grammar. |
| `franz.affinity/shard-size` | Integer ≥ 1, default `1`. How many distinct clusters to spread the channel's shards across. |
| `franz.taint/toleration` | `<taint-name>:<effect>` (comma-separated for several). Lets the channel be placed on a cluster carrying a matching `no-creation` taint. |

### On the Kafka Cluster (`KafkaCluster.labels`)

| Label | Meaning |
|---|---|
| `franz.taint` | `<taint-name>:<effect>`, `effect ∈ { no-creation, drain }`. Repels channels (see Taints). |
| `franz.affinity/weight` | Integer, default `1`. Relative preference when several candidates remain. Higher wins. |

Non-`franz.*` labels on either side are the free-form fleet metadata that the
selector expressions are written against (`my-fleet/tier=high-volume`, …).

## Selection algorithm

For one Async Channel with `channel_partitions = N` shards:

1. **Candidates** — every Kafka Cluster with `state = ACTIVE` whose labels satisfy
   `franz.affinity/selector`. An **absent** `franz.affinity/selector` yields
   **no candidates** — placement is opt-in; the channel's shards stay unplaced
   until a selector is added.
2. **Anti-affinity** — drop candidates whose labels satisfy
   `franz.antiaffinity/selector`.
3. **Taints** — drop candidates with a `franz.taint` of effect `drain`
   (untolerable); drop those with effect `no-creation` unless the channel carries
   a matching `franz.taint/toleration`.
4. **Choose clusters** — take `min(shard-size, |candidates|)` clusters, ordered by
   `franz.affinity/weight` descending, ties broken by cluster `name` ascending
   (deterministic). `shard-size` may exceed `N` — it is still capped at
   `|candidates|` and simply spreads the shards thinner.
5. **Distribute shards** — assign the `N` shards round-robin across the `k` chosen
   clusters: shard `i` → `chosen[i mod k]`, so when `N` is not a multiple of `k`
   the **earlier** (higher-weight, then lower-named) clusters take the remainder.
   Franz materialises a `kafka_topic` row for each placed shard, with
   `kafka_cluster` set.

If the candidate set is empty (no selector, selector matches nothing, or every
match is filtered by anti-affinity/taints), **no rows are created** for the
affected shards. The **retry sweep** (configurable, default 30 s —
`FRANZ_PLACEMENT__SWEEP_INTERVAL`, `0` disables) re-runs steps 1–5 for every
channel with fewer live shard rows than `channel_partitions`, so a shard places
itself as soon as a cluster is registered, resumed, or re-labelled into
eligibility. Placement also runs **immediately** on the events that can change
the outcome (channel create / `franz.*` relabel; cluster create / relabel /
pause / resume / delete), so the sweep is a safety net rather than the primary
trigger.

## Re-placement

A shard that is **already placed** is only ever moved by the migration flow
(`003.13`), never silently. When a channel's `franz.*` labels change, or a
cluster is re-labelled / paused / deleted / `drain`-tainted so a placed shard's
cluster no longer satisfies the channel's affinity:

- The shard is marked **misplaced** — `KafkaTopic.misplaced` / `misplaced_reason`
  (`003.6`), surfaced by the API and console. Removing `franz.affinity/selector`
  from a channel entirely marks **every** placed shard misplaced (no selector ⇒
  no candidates ⇒ every cluster fails affinity).
- Franz queues a migration (`003.13`) to move it to a currently-eligible cluster
  — **auto-relocate**. Until the migration flow lands, a misplaced shard stays
  where it is and only the marker is set (**interim behaviour** — deliverable 13
  ships the marker; the move is deliverable 17).
- The marker is **cleared automatically** on the next placement pass once the
  shard's cluster satisfies the rules again (e.g. the cluster is resumed or
  re-labelled back into eligibility). It never bumps `generation`.
- Weight changes or a new higher-weight cluster appearing do **not** move a placed
  shard, and a **`no-creation`** taint on the shard's own cluster does not
  misplace it — only actually losing eligibility (affinity, `PAUSED`/`DELETED`,
  or a `drain` taint) does.

New/unplaced shards always use the current rules (the retry sweep above).

## Taints

| Effect | On a cluster it… |
|---|---|
| `no-creation` | blocks **new** shard placement; existing shards stay and are **not** marked misplaced. A channel with a matching `franz.taint/toleration` is exempt. |
| `drain` | blocks new placement **and** marks every shard on the cluster **misplaced** for migration to another eligible cluster. Cannot be tolerated. |

Typical uses: `decommission:drain` (retire a cluster), `unstable:no-creation`
(incident isolation), `dedicated-<team>:no-creation` (reserve a cluster for
tolerating channels), `maintenance:no-creation` (rolling restart window).

## Invariants

- A `KafkaTopic` row exists only for a **placed** shard — it always has a
  `kafka_cluster`, and that cluster's labels satisfied the channel's affinity at
  placement time. An unplaced shard has no row (ADR-API-009).
- A shard is never placed on a cluster with a `drain` taint or on a `no-creation`
  cluster the channel does not tolerate.
- Placement is deterministic: same channel labels + same cluster set ⇒ same
  assignment (weight then name ordering).
- `shard-size` caps the cluster spread, not the shard count — `N` shards may
  share a cluster when `N > shard-size`.

## Cross-entity behavior

- **Async Channel** (`003.4`) — placement runs on create and when a channel's
  reserved placement labels (`franz.affinity/*`, `franz.antiaffinity/*`,
  `franz.taint/toleration`) change; editing a channel's other labels is a no-op
  for placement.
- **Kafka Cluster** (`003.3`) — `state` gates candidacy (`PAUSED`/`DELETED`
  clusters are never candidates); editing **any** of a cluster's labels can add
  or remove it from a channel's candidate set, so a cluster label edit re-runs
  placement for the realm. Cluster create / pause / resume / delete run it too.
- **Kafka Topic** (`003.6`) — the output is a `kafka_topic` row per **placed**
  shard, with `kafka_cluster` set; a `drain` taint or a `misplaced` shard feeds
  the migration flow (`003.13`).
- **Governance** (`003.8`) — a Policy may add/remove a channel's `franz.affinity/*`
  and `franz.antiaffinity/*` labels or a cluster's `franz.taint` (`no-creation`
  **or** `drain`), which triggers the retry sweep and/or migrations exactly as an
  operator edit would.

## Open questions

1. ~~**`shard-size` vs `channel_partitions`**~~ — **resolved** (deliverable 13):
   uneven round-robin gives the remainder to the earlier (higher-weight, then
   lower-named) clusters (`chosen[i mod k]`); `shard-size` may exceed
   `channel_partitions` and is simply capped at `|candidates|`.
2. **Placement preview** — whether `AsyncChannelService` gains a dry-run
   `PreviewPlacement` RPC for the console create flow. Still open.
3. **Multiple tolerations encoding** — resolved for now: comma-separated
   `<name>:<effect>` in one `franz.taint/toleration` value (`003.1`). Revisit if
   a structured form is needed.
4. **`franz.affinity/weight` as a spread heuristic** — weight biases only *which*
   clusters are chosen, not *how many* shards each gets (round-robin is even).
   Whether weight should also skew the distribution is still open.
5. ~~**Retry-sweep interval**~~ — **resolved** (deliverable 13): configurable,
   `FRANZ_PLACEMENT__SWEEP_INTERVAL`, default 30 s, `0` disables; event triggers
   (channel/cluster changes) run in addition, so the sweep is a backstop.
