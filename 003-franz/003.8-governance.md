# Governance

Status: **draft**

Shapes & RPCs: [`governance.proto`](../../franz/api/franz/v1/governance.proto) —
`Policy`, `Matcher`, `Entity`, `Limit`, `Operator`, `Action`, `ActionKind`,
`PolicyAction`, `Indicator`, `GovernanceService`. Indicator samples arrive via
[`telemetry.proto`](../../franz/api/franz/v1/telemetry.proto).

## Concepts

Governance lets an **Async Admin** attach fleet-wide rules that make Franz **react**
to how resources actually behave. A **Policy** watches one **Indicator**; when the
latest sample crosses a **Limit**, the policy runs its **Actions** on every
resource its **Matcher** selects.

**Reactive only — no admission control.** A policy never rejects or delays a
`Create` / `Update`. It observes an indicator and mutates Franz's *declared*
state after the fact; the normal reconciliation path (`003.6`) then realises the
change. The old "reject topic creation / update" actions are gone.

```
Telemetry Agent ──sample──▶ Indicator ──▶ Policy (limit crossed?)
                                              │ yes
                                     Actions mutate declared state
                                              │
                                     reconciliation realises it
                                              │
                                     PolicyAction recorded
```

## Key shapes

- **`Policy`** — `indicator` (name), `matcher`, `limit`, `actions` (ordered),
  `weight` (tie-break, higher wins), `enabled`, `last_fired_at`. `name` is the
  realm-unique key.
- **`Matcher`** — `entity` (`ASYNC_CHANNEL` / `KAFKA_TOPIC` / `KAFKA_CLUSTER`) +
  `selector` (a `003.1` label selector; empty = every resource of that entity).
- **`Limit`** — `operator` (`<`, `≤`, `=`, `≠`, `≥`, `>`) + `value`, a **string**
  encoded in the indicator's unit (`"150Gi"`, `"3"`, `"90d"`). A lower+upper band
  is two policies.
- **`Action`** — `kind` + positional `args`:

  | Kind | args |
  |---|---|
  | `ADD_LABEL` | `[key, value]` |
  | `REMOVE_LABEL` | `[key]` |
  | `SET_STATUS` | `[status]` |
  | `UPDATE_FIELD` | `[field, value]` |
  | `INCREASE_FIELD_BY` | `[field, amount]` |
  | `DECREASE_FIELD_BY` | `[field, amount]` |

  `amount` may be absolute or a percentage (`"50%"`). The set of `(entity, field)`
  an action may write is a whitelist — an open question.
- **`Indicator`** — read-only over the API. `unit`, `applies_to` (entity),
  `source_agents`, `health` (`HEALTHY` / `STALE`), `last_sample_at`,
  `staleness_threshold`. Published by Telemetry Agents; never written through
  `GovernanceService`.
- **`PolicyAction`** — the audit record of one automated change: `occurred_at`,
  `resource_orn`, `indicator_value`, `action`, `result`. Read via
  `ListPolicyActions`.

## Evaluation

For each enabled policy, whenever a fresh sample of its indicator arrives (cadence
— see Open questions):

1. If the indicator is `STALE` (older than `staleness_threshold`) → **do not
   act**.
2. For every resource of `matcher.entity` whose labels satisfy `matcher.selector`,
   take that resource's latest value of `indicator`.
3. If `value <operator> limit.value` holds → the policy **triggers** for that
   resource.
4. Apply `actions` in order to the resource's declared state; record one
   `PolicyAction` per action; set `last_fired_at`.

When several triggered policies target the **same resource and field**, the
higher `weight` wins. Equal weight, anti-thrash, and re-fire suppression are open
questions.

## Dry run

`DryRunPolicy` evaluates an **inline, unsaved** policy definition (`indicator` +
`matcher` + `limit` + `actions`; `weight` / `enabled` ignored) against the latest
samples and returns, per matched resource, the `indicator_value` and
`would_trigger`. It performs **no mutation** and writes **no** `PolicyAction`.

## Invariants

- `name` unique per realm; `matcher.entity ≠ UNSPECIFIED`;
  `limit.operator ≠ UNSPECIFIED`; `actions` non-empty; each action's `args` arity
  matches its `kind`.
- A disabled policy never triggers. A policy whose indicator is stale never
  triggers.
- `applies_to` and `matcher.entity` must agree — a policy cannot read a
  cluster-scoped indicator for a channel matcher.
- Actions only ever change **declared** state; they never call agents directly and
  never touch access policies (`003.5`).
- `INCREASE_FIELD_BY` / `UPDATE_FIELD` on `KafkaTopic.partitions` may only raise it
  (`003.6`).

## Cross-entity behavior

- **Targets** — `ASYNC_CHANNEL` (`003.4`), `KAFKA_TOPIC` (`003.6`),
  `KAFKA_CLUSTER` (`003.3`). A `SET_STATUS` maps to that entity's state machine
  (e.g. pause a channel); a label action can flip placement (`003.7`) or match
  other policies.
- **Indicators** — the console Governance landing page reads `ListIndicators`
  (count, `health`, `last_sample_at`) above the policy list; samples come from
  `telemetry.proto`.
- **Reconciliation** — a policy that changes `topic_configuration` or
  `partitions` produces the same effect as an operator edit: the shard goes
  `READY → PENDING → READY`.
- **Auditability** — every automated change is a `PolicyAction`; there is no
  silent mutation.

## Open questions

1. **Write whitelist** — the exact `(entity, field, allowed operations)` matrix
   for `UPDATE_FIELD` / `INCREASE_FIELD_BY` / `DECREASE_FIELD_BY`, and the allowed
   `SET_STATUS` values per entity.
2. **Equal-weight conflict** — two triggered policies with the same `weight` and
   opposing actions on one field: deterministic order, reject at create, or
   last-write-wins?
3. **Anti-thrash** — cooldown after `last_fired_at`, or require the indicator to
   cross back over the limit before the policy may fire again (hysteresis).
4. **Evaluation trigger & cadence** — act on every incoming sample vs. a periodic
   sweep; the acceptable lag between sample and action.
5. **Dry run of a saved policy** — allow `DryRunPolicy` by policy `name`, and add
   a `simulated_effect` showing the resulting field values, not just
   `would_trigger`.
6. **Unknown indicator** — reject `CreatePolicy` when the `indicator` is not a
   registered `Indicator`, or accept it (dormant until the indicator appears)?
7. **Range limits** — keep two-policy bands, or add a range/`BETWEEN` operator.
8. **Indicator provisioning** — are `Indicator` records auto-created by an agent's
   first sample, or pre-registered by an admin (and by which RPC — there is no
   `CreateIndicator` today)?
