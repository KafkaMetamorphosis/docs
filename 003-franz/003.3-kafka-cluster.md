# Kafka Cluster

Status: **ready**

Shapes & RPCs: [`kafka.proto`](../../franz/api/franz/v1/kafka.proto) — `KafkaCluster`,
`ConnectionString`, `ConnectionType`, `KafkaClusterService`.

## Concepts

A Kafka Cluster is a **registration**, not a managed resource. It records where a
real Kafka cluster is, the fleet context it sits in (labels), its default topic
configuration, and optionally which Cluster Provider agent stands it up. Franz
**never connects to it** — registering does not validate connectivity, discover
brokers, or configure authentication.

The registry is a **discovery layer**: the Kafka Topics an Async Channel generates
are placed on clusters by matching the channel's `franz.affinity/*` labels against
cluster labels (`003.7-placement-and-selection.md`); Resource Provider agents
reconcile the real topics against those clusters.

## Key fields

| Field | Notes |
|---|---|
| `name` | Client-provided, immutable, natural key in every path. |
| `orn` | Server-assigned. |
| `connection_strings` | `repeated ConnectionString` (`bootstrap_urls` + `type`). Today `type` is only `PLAINTEXT`; the field is repeated so authenticated connection types can be added without a breaking change. |
| `labels` | Fleet-context metadata (env, region, shard, …) matched by placement selectors and List filters. Also carries **`franz.provisioning/*`** intent labels a Cluster Provider agent's recipe reads (`003.1`, `../004-local-kafka-docker-agent/`). |
| `cluster_configuration` | `map<string,string>` — the default Kafka topic config for topics on this cluster; layer 1 of the config merge (`003.6-kafka-topic.md`). |
| `cluster_provider_agent` | Optional agent `name`. Free string — **not validated** against the agent registry. Empty means the infrastructure is managed outside Franz — the cluster is still fully usable and topics still reconcile against it. |
| `state` | `KafkaClusterState` — `ACTIVE` / `PAUSED` / `DELETED`. Server-managed; see below. |
| `created_at` / `updated_at` | Audit pair. |

## State transitions

A cluster has a persisted lifecycle `state` with three values:

| State | Meaning |
|---|---|
| `ACTIVE` | Registered and eligible for placement. Set at registration. |
| `PAUSED` | Registered but excluded from **new** placement. Existing Kafka Topics on the cluster are untouched and keep reconciling. |
| `DELETED` | Soft-deleted, terminal. The record is retained for audit; the `name` is not freed. |

```
(create) ──▶ ACTIVE ──PauseKafkaCluster──▶ PAUSED
               ▲──────ResumeKafkaCluster──────┘
   ACTIVE / PAUSED ──DeleteKafkaCluster──▶ DELETED   (terminal)
```

- `PauseKafkaCluster` / `ResumeKafkaCluster` toggle `ACTIVE ↔ PAUSED`.
- Any operation on a `DELETED` cluster fails with `FAILED_PRECONDITION`.
- Richer health/status (degraded, draining, agent-reported) is **not** modelled
  yet — only these three states exist for now.

## Invariants

- `name` is unique within a realm and immutable.
- `connection_strings` is non-empty at create.
- `cluster_provider_agent` is an unvalidated string — Franz does not check that
  the named agent exists or is a Cluster Provider.
- `state` is server-managed; clients change it only through the pause/resume/delete
  RPCs, never through `UpdateKafkaCluster`.
- Deleting a cluster that still hosts Kafka Topics fails with
  `FAILED_PRECONDITION` — the safe-delete rules are an open question
  (`003.11-lifecycle-and-operations.md`).

## Cross-entity behavior

- **Placement** — the reconciler matches an Async Channel's `franz.affinity/*`
  labels against cluster labels, applies `franz.affinity/shard-size`, and excludes
  clusters via `franz.antiaffinity/*` or taints (`003.7`).
- **Config merge** — `cluster_configuration` is the base layer beneath a Kafka
  Topic's `topic_configuration` (`003.6`). Editing `cluster_configuration` affects
  **only topics created after the change**; already-created topics keep their
  materialized config and are not re-reconciled.
- **Provider link** — one Cluster Provider agent may be referenced by many
  clusters. The agent stands up and maintains the substrate from the cluster's
  `franz.provisioning/*` intent and reports back what it provisioned; that
  observed status is kept as an append-only event log, separate from `state`
  (operator intent). Contract + local Docker recipe: `../004-local-kafka-docker-agent/`.
- Editing a cluster's `labels` can make it newly eligible (or ineligible) for
  existing channels — placed shards that lose eligibility are marked *misplaced*
  and queued for migration (`003.7`, `003.13`).
- Pausing a cluster removes it from **new** placement only; it does not move or
  drain the topics already on it.
- **Governance** (`003.8`) — a Policy may `SET_STATUS` the cluster
  (`PAUSED` / `ACTIVE` / `DELETED`), edit its non-`franz.*` labels and
  `cluster_configuration` keys, and set `franz.taint` to `no-creation` **or**
  `drain` when an indicator limit is crossed.
